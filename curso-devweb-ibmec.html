1.2 Arquitetura Cliente-Servidor, Métodos e Status HTTP (Aula 02)

O Cliente (navegador/app) monta a URL e envia uma Requisição HTTP. O Servidor processa e devolve uma Resposta (HTML, CSS, JS, JSON). O navegador então constrói a árvore DOM (Document Object Model).

Papel do Navegador

• HTML (Estrutura): Títulos, textos, imagens, links.

• CSS (Estilo): Cores, fontes, layout.

• JS (Comportamento): Cliques, animações e lógica dinâmica na árvore DOM.

Verbos / Métodos HTTP

• GET: Solicita/busca dados sem alterá-los.

• POST: Envia novos dados (ex: formulário/cadastro).

• PUT: Atualiza um recurso por completo.

• DELETE: Remove um recurso do servidor.

Códigos de Status HTTP

• 2xx Sucesso: 200 OK

• 3xx Redirecionamento: 301 Moved

• 4xx Erro do Cliente: 404 Not Found

• 5xx Erro do Servidor: 500 Internal Error

HTTP é Sem Estado (Stateless): Cada requisição é independente; o servidor não lembra da anterior. Para manter um usuário logado, usamos Cookies (pequenos dados salvos no navegador e reenviados a cada requisição) e Sessões (reconhecimento do "crachá" no servidor).

1.3 IP, Portas, Anatomia de URL, DNS e HTTPS (Aulas 02 e 03)

IP, Domínio, DNS e Portas

• Endereço IP: Identificador numérico da máquina (ex: 192.0.2.1). Como o endereço de um prédio.

• Portas (Entrada de cada serviço): Como o número do apartamento. 80 (HTTP), 443 (HTTPS), 22 (SSH - acesso remoto seguro), 21 (FTP - transferência de arquivos).

• Consulta DNS (Catálogo da Internet): 1. Você digita ibmec.br → 2. Resolver DNS consulta os Servidores DNS → 3. Devolve o IP 192.0.2.1 → 4. Navegador acessa o Servidor Web pelo IP.

HTTP vs HTTPS (Segurança)

• HTTP: Texto puro. Qualquer pessoa na mesma rede pode interceptar e ler.

• HTTPS: Camada de criptografia TLS/SSL. Protege através de 3 pilares:

  • 1. Criptografia: Embaralha os dados matematicamente.
  • 2. Certificado Digital: Emitido por autoridade confiável, comprova a identidade do site.
  • 3. Cadeado do Navegador: Indica conexão segura e certificado válido.

MÓDULO 2: HTML5 Completo (Aulas 04 a 10)

Marcação & Semântica

2.1 Estrutura Mínima, Tags e Atributos (Aula 04)

HTML (HyperText Markup Language) é uma linguagem de marcação (não de programação, pois não possui variáveis, condicionais ou loops). Evolução: 1991 (1ª versão) → 1995 (HTML 2.0) → 1999 (HTML 4.01) → 2014 (HTML5).

• Tags Pareadas: Têm abertura e fechamento envolvendo conteúdo (<p>...</p>, <h1>...</h1>).

• Tags Vazias (Self-Closing): Elemento único, sem fechamento (<img>, <br>, <input>, <meta>).

• Atributos Principais: id (identificador único na página), class (agrupador reutilizável), src (origem), href (destino), alt (texto alternativo de acessibilidade).

• Hierarquia: Elementos aninhados formam relações de pai, filho e neto.

<!DOCTYPE html> <!-- 1ª linha: declara HTML5 --> <html lang="pt-br"> <!-- Elemento raiz único --> <head> <!-- Metadados invisíveis --> <meta charset="UTF-8"> <!-- Acentos --> <title>Título da Aba</title> <link rel="stylesheet" href="estilo.css"> </head> <body> <!-- Conteúdo visível --> <h1>Bem-vindo!</h1> </body> </html>

2.2 Títulos, Parágrafos, Ênfase e Listas (Aula 05)

• Títulos (<h1> a <h6>): Use apenas um <h1> por página. Não pule níveis (ex: de h2 para h4) nem escolha pelo tamanho visual (use CSS para tamanho).

• Parágrafo vs Quebra: <p> cria um bloco com espaçamento; <br> apenas força quebra de linha.

• Ênfase Semântica vs Visual: Prefira <strong> (importância real/negrito) em vez de <b> (só visual), e <em> (ênfase real/itálico) em vez de <i> (só visual). Leitores de tela entendem a semântica.

<!-- Lista Não Ordenada (ul) com Lista Ordenada (ol) aninhada DENTRO do <li> --> <ul> <li>Frontend <ol> <li>HTML5</li> <li>CSS3</li> </ol> </li> <li>Backend</li> </ul>

2.3 Links, Navegação e Imagens (Aula 06)

• Link Absoluto: URL completa (href="https://ibmec.br") para sites externos.

• Link Relativo: Caminho local (href="sobre.html") para páginas do mesmo projeto.

• Nova aba: target="_blank" abre em outra guia (boa prática: adicionar rel="noopener").

• Âncora Interna: Link com href="#contato" rola até o elemento com id="contato" na mesma página.

• Imagens (<img>): Exige src e alt descritivo. Formatos: JPG (fotos), PNG (transparência), SVG (ícones/vetores).

<nav> <a href="index.html">Início (Relativo)</a> <a href="#contato">Ir para Contato (Âncora)</a> <a href="https://ibmec.br" target="_blank" rel="noopener">Ibmec</a> </nav> <img src="logo.png" alt="Logo do Ibmec" width="200"> <h2 id="contato">Seção de Contato</h2>

2.4 Tabelas (Aula 07) & Tags Semânticas (Aula 08)

Tabelas HTML (Apenas para Dados Tabulares!)

• <table> (container), <tr> (linha), <th> (célula de cabeçalho em negrito/centralizada), <td> (célula de dado).

• Seções semânticas: <thead>, <tbody> e <tfoot>.

• Mesclagem: colspan="2" (mescla 2 colunas) e rowspan="2" (mescla 2 linhas). Nunca use tabelas para layout!

Tags Semânticas (Acessibilidade, SEO e Legibilidade)

  • • <header>: Cabeçalho da página ou seção.
  • • <nav>: Menu principal de links de navegação.
  • • <main>: Conteúdo principal e único da página.
  • • <section>: Agrupamento temático dentro da página (ex: seção "Nossos Serviços").
  • • <article>: Conteúdo independente e completo que faz sentido sozinho (post de blog, notícia).

2.5 Formulários HTML5 & Validação Nativa (Aulas 09 e 10)

• <form action="/url" method="post">: action define para onde enviar; method define o verbo HTTP (GET ou POST).

• <label for="id">: Liga o rótulo ao id do campo (clicar no texto foca o input). O atributo name identifica o dado enviado ao servidor.

• Tipos de Input: text, email, password, number, checkbox (múltipla escolha), radio (escolha única), date, color, range, tel, url.

3.2 Box Model, Cascata, Especificidade e Herança (Aula 12)

• Camadas (dentro → fora): content → padding → border → margin.

• Atalhos: 2 valores (padding: 10px 20px = vertical e horizontal). 4 valores = topo, direita, baixo, esquerda (sentido horário). margin: 0 auto centraliza bloco na horizontal.

• Display: block (ocupa linha toda), inline (ignora width/height), inline-block (fica na linha mas aceita width/height), none (remove elemento).

• Especificidade (Peso): Inline (1000) > ID (100) > Classe/Atributo/Pseudo-classe (10) > Elemento (1). Empate: vence a última regra declarada. !important vence tudo (evite).

Exemplos: #menu a = 101 | .nav a:hover = 21 | #topo p.destaque = 111 | ul li a = 3

• Herança: Herdados: color, font-*, line-height, text-align. NÃO herdados: margin, padding, border, background, width, height. (inherit força herança).

/* Boa prática global no início do CSS */ *, *::before, *::after { box-sizing: border-box; /* width inclui padding e border */ } .caixa { width: 200px; padding: 20px; border: 5px solid navy; } /* content-box (padrão): 200 + 40 + 10 = 250px reais! border-box (recomendado): 200px finais exatos! */

3.3 Cores, Tipografia, Web Fonts, Sombras e Gradientes (Aula 13)

• Formatos de Cor: Hexadecimal (#022451), RGB (rgb(2, 36, 81)), RGBA (rgba(0,0,0,0.5)) e HSL (hsl(214, 95%, 16%)).

• PEGADINHA opacity deixa o elemento inteiro (e seus filhos) transparente. rgba() aplica transparência apenas na cor.

• PEGADINHA Gradientes vão em background ou background-image, nunca em background-color.

• Sombras: box-shadow: x y blur spread(opcional) cor; (inset = sombra interna). Já text-shadow: x y blur cor; não possui spread-radius.

body { font-family: "Poppins", Arial, sans-serif; /* termina em genérica */ line-height: 1.5; } .card { box-shadow: 0 4px 12px rgba(0,0,0,.15); background: linear-gradient(135deg, #022451, #F5A623); /* ou radial-gradient(circle, white, navy) */ } h1 { text-shadow: 2px 2px 4px rgba(0,0,0,.4); }

3.4 CSS Flexbox: Container & Itens — 1 Dimensão (Aula 14)

• No Container (display: flex):

  • - flex-direction: row (padrão: eixo principal horizontal), row-reverse, column, column-reverse.
  • - justify-content: Alinha no eixo principal (flex-start, center, space-between, space-around, space-evenly).
  • - align-items: Alinha no eixo transversal/cruzado (stretch [padrão], center, flex-start, flex-end).
  • - flex-wrap: nowrap (padrão: espreme na mesma linha) ou wrap (quebra linha).
🚨 Pegadinha Clássica: Com flex-direction: column, os eixos trocam de papel! justify-content passa a controlar a vertical e align-items a horizontal.

• Nos Itens (Filhos): flex-grow (padrão 0), flex-shrink (padrão 1), flex-basis (padrão auto). Atalho flex: 1 (equivale a 1 1 0%). align-self (sobrescreve align-items para 1 item) e order (padrão 0; valores menores como -1 aparecem primeiro sem mudar o HTML).

/* Centralizar perfeitamente na tela inteira */ .tela { display: flex; justify-content: center; align-items: center; height: 100vh; } /* 3 colunas proporcionais (1x, 2x, 1x) */ .col-1 { flex: 1; } .col-2 { flex: 2; } /* Recebe o dobro do espaço */

3.5 CSS Grid: Fundamentos — 2 Dimensões (Aula 15)

• Quando usar: Grid para a estrutura macro da página (2D: linhas e colunas simultaneamente); Flexbox para alinhar componentes em uma direção (1D).

• Fração e Repetição: 1fr representa 1 fração do espaço livre. repeat(3, 1fr) cria 3 colunas iguais.

• PEGADINHA Contagem de Linhas de Grade: Uma grade de N colunas tem N+1 linhas! Portanto, grid-column: 1 / 3 começa na linha 1 e termina na linha 3 (ocupando 2 colunas, equivalente a span 2). 1 / -1 ocupa a largura toda.

/* Grid Responsivo Automático SEM Media Query */ .galeria { display: grid; grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); gap: 16px; } /* Layout com Áreas Nomeadas */ .pagina { display: grid; grid-template-columns: 200px 1fr; grid-template-areas: "topo topo" "menu conteudo" "rodape rodape"; } .topo { grid-area: topo; }

3.6 Design Responsivo — Parte 1 e Parte 2 (Aula 16)

• Meta Viewport: Obrigatória no <head> (<meta name="viewport" content="width=device-width, initial-scale=1.0">) para celulares não encolherem a página como desktop.

• Mobile-First (Recomendado): CSS base escrito para telas pequenas e @media (min-width: ...) para adicionar colunas em telas maiores. (Desktop-first usa max-width).

• Breakpoints Comuns: 576px (Mobile grande), 768px (Tablet), 992px (Desktop), 1200px (Telas grandes).

• Unidades Relativas: % (relativo ao pai), vw / vh (1% da largura/altura da janela/viewport), em (relativo à fonte do pai/elemento — pode compor em cascata), rem (sempre relativo à raiz <html>, padrão 16px; truque: html { font-size: 62.5%; } faz 1rem = 10px).

• Imagens e Tipografia Fluida: img { max-width: 100%; height: auto; }, object-fit: cover, e função clamp(mínimo, ideal, máximo).

/* Mobile-First: 1 coluna no celular, 2 no tablet, 3 no desktop */ .grid { display: grid; grid-template-columns: 1fr; gap: 16px; } @media (min-width: 768px) { .grid { grid-template-columns: 1fr 1fr; } } @media (min-width: 992px) { .grid { grid-template-columns: repeat(3, 1fr); } } /* Tipografia fluida (mín, ideal fluido, máx) */ h1 { font-size: clamp(1.5rem, 4vw, 3rem); }

4.1 Variáveis, Tipos, Coerção, Falsy e Controle de Fluxo (Encontro 1 / Aula 17)

• const vs let: Use const por padrão e let quando a variável for reatribuída. Evite var.

• PEGADINHA const impede reatribuir (arr = [] dá erro), mas NÃO impede alterar o conteúdo interno de arrays e objetos (arr.push(1) funciona normalmente!).

• PEGADINHA typeof null e typeof [] ambos retornam "object"!

• Coerção e Igualdade: Prefira sempre === (compara valor e tipo) a == (converte tipo). O operador + com string concatena ("5" + 3 → "53"), enquanto - converte para número ("5" - 3 → 2).

• Valores Falsy (Apenas 6!): false, 0, "" (string vazia), null, undefined e NaN. Todo o resto é Truthy, inclusive "0", [] (array vazio) e {} (objeto vazio)!

• Loops e Entrada: prompt() devolve sempre string (use Number(prompt(...))). O laço do { ... } while (cond) executa pelo menos 1 vez. break encerra o loop; continue pula para a próxima volta.

4.4 Persistência com JSON e localStorage (Encontro 4 / Aula 20)

• JSON: Formato textual para transporte/armazenamento. JSON.stringify(obj) converte Objeto/Array → Texto. JSON.parse(texto) converte Texto → Objeto/Array.

• Regras do localStorage:

  • - Só armazena texto (strings) (por isso exige stringify / parse).
  • - Limite de cerca de 5 MB por site.
  • - Os dados sobrevivem ao fechar a aba ou navegador.
  • - getItem("chave") devolve null se a chave não existir.
  • - Sem segurança: Nunca guarde senhas ou dados sensíveis.

• Padrão de Arquitetura: O array JavaScript é a fonte da verdade (não o DOM). Fluxo: alterar array → salvar() → renderizar().

const CHAVE = "tarefas_app"; function salvar(tarefas) { localStorage.setItem(CHAVE, JSON.stringify(tarefas)); } function carregar() { const salvo = localStorage.getItem(CHAVE); return salvo ? JSON.parse(salvo) : []; }

4.5 Assíncrono, Promises, Async/Await e Fetch API (Tema #1 da Revisão!)

• Event Loop: console.log("1"); setTimeout(() => console.log("2"), 0); console.log("3"); imprime 1, 3, 2 porque o callback assíncrono aguarda a pilha principal esvaziar.

• Promises (3 Estados): pending (pendente), fulfilled (resolvida → .then) e rejected (rejeitada → .catch). .finally roda sempre.

• Regras de Ouro do async / await e fetch:

  • 1. await só pode ser usado dentro de uma função async (ou no topo de módulos ES), e toda função async devolve uma Promise.
  • 2. PEGADINHA O fetch() NÃO rejeita (não cai no catch) em erros HTTP 404 ou 500! Ele só rejeita automaticamente em falha de rede (sem internet). Você DEVE checar if (!resp.ok) throw new Error(...).
  • 3. São necessários dois await: o 1º para os cabeçalhos da resposta (await fetch(url)) e o 2º para ler o corpo JSON (await resp.json()).
  • 4. ViaCEP: Limpar com cep.replace(/\D/g, "") (8 dígitos). CEP inexistente retorna status 200 com { erro: true }!
async function buscarUsuarios(url) { statusEl.textContent = "Carregando..."; try { const resp = await fetch(url); // 1º await if (!resp.ok) { throw new Error("Erro HTTP: " + resp.status); } const dados = await resp.json(); // 2º await statusEl.textContent = "Sucesso!"; renderizarLista(dados); } catch (erro) { statusEl.textContent = "Falha ao carregar dados."; } }
